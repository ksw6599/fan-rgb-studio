# RGB 색상이 안 바뀌거나 효과가 멈출 때

## 색상을 고정하고 싶을 때

**RGB 연결 → 장치 선택 → 단색으로 켜기 → 색상·밝기 → 조명 설정 적용** 순서로 사용합니다. Static/Direct 같은 단색 모드는 선택한 색에 고정됩니다.

Rainbow/Spectrum/Random 등 일부 효과는 하드웨어가 색상을 자동 생성합니다. 그 효과가 지정 색상을 지원하지 않으면 HEX 입력을 비활성화하고 안내를 표시합니다. 해당 효과를 사용하면서 HEX만 바꿔도 색상이 바뀌는 것은 아닙니다.

다중 팔레트를 사용하는 효과는 첫 번째 색만 바꾸고 나머지 색은 보존합니다. 팔레트 전체를 한 색으로 덮어써서 움직임이 사라진 것처럼 보이게 하지 않습니다.

## 움직이는 효과가 멈춘 것처럼 보일 때

1. 효과 목록에서 움직이는 효과를 선택합니다. 단색과 Off는 움직이지 않습니다.
2. 속도 조절을 지원하면 **효과 속도**를 확인합니다. 0은 일부 장치에서 정지를 뜻하지만 다른 장치에서는 의미가 다릅니다.
3. **효과 다시 시작**은 속도를 지원하는 효과를 중간 속도 50%로 다시 전송합니다. 속도가 없는 효과도 선택한 모드를 다시 전송합니다.
4. 지원하는 속도·밝기·방향·색상 방식만 장치에 보냅니다. 전체 장치 전용 효과는 구역별로 전송하지 않습니다.

실제 속도의 의미와 지원 효과는 장치별로 다릅니다. UI는 장치가 보고한 지원 정보를 사용합니다.

## 응답이 없거나 적용이 실패할 때

- **다시 검색**은 목록만 갱신합니다. 현재 효과를 저장된 예전 색상으로 바꾸지 않습니다.
- **RGB 복구**는 이 앱이 시작한 OpenRGB 엔진을 종료하고 다시 연결합니다. 팬 속도 worker나 PA120 숫자 전송은 종료하지 않습니다.
- 복구 중에는 이전 조명을 자동으로 다시 쓰지 않습니다. 원하는 효과를 선택해 적용하거나 **저장된 조명 다시 적용**을 누릅니다.
- 외부 OpenRGB 엔진은 강제 종료하지 않습니다. 그 프로그램에서 다시 시작한 후 연결해야 합니다.
- 다른 RGB 프로그램이 같은 장치를 제어하면 서로 덮어쓸 수 있습니다. 해당 프로그램과의 동시 제어 여부도 확인합니다.

통신은 시간 제한을 적용하고, 실패 후 조작 버튼이 다시 활성화됩니다. 지원하지 않는 저장 효과는 부팅 때 반복 전송하지 않습니다. USB 재설정이나 펌웨어 변경은 자동 수행하지 않습니다.

## 진단 전달

1. **RGB 진단 저장**을 누릅니다.
2. 왼쪽 **진단 폴더 열기**에서 `rgb-diagnostics.json`을 찾습니다.
3. 파일과 실제 증상을 이슈 또는 문의에 첨부합니다.

파일에는 앱 버전, 엔진 상태, RGB 장치 이름, 효과의 지원 기능·속도 범위, 구역 이름과 LED 수, 마지막 오류가 들어갑니다. 사용자·PC 이름, USB 경로, 시리얼 번호, CPU/GPU 센서 전체 정보는 넣지 않습니다. 연결에 실패하면 목록에 남은 정보를 사용할 수 있어 마지막 오류도 함께 확인해야 합니다.

## 검증 범위

v1.7.0은 SDK3 프로토콜과 효과 플래그에 맞춘 범용 처리 개선입니다. 여러 가상 장치의 TCP 응답과 실제 WPF 조작을 검사했습니다. 알 수 없는 모든 메인보드·허브에서 실물 제어가 성공한다고 보장하지 않습니다. 엔진의 응답 확인과 실제 LED 변화 확인은 구분합니다.
